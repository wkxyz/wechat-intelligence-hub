# Existing Bot Host Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task by task.

**Goal:** Let existing Bot hosts use the verified local WeChat connector through native tools and MCP.
**Architecture:** A paired native client talks to the existing loopback gateway. A stdio MCP adapter exposes two read-only tools; the connector exports token-free launch configuration.
**Tech Stack:** Python standard library, existing Reader and Tkinter, GitHub Actions portable builds.
**Spec:** docs/superpowers/specs/2026-10-11-bot-host-design.md

## Global Constraints
- Protocol versions 2025-11-25 and 2025-06-18; UTF-8 newline-delimited JSON-RPC.
- Only status and search/topic/history/reply; account keys never leave Reader.
- No public listener, automatic tunnel, model calls, retry loop, report or message sending.
- Tokens in private local files only; connector restart and revocation invalidate them.
- Python 3.11+ for distributed builds; Windows x64 and Mac arm64/x64.

## Review Focus
- Untrusted params cannot select paths, SQL or destinations.
- Oversized input/output and duplicate tool requests remain bounded.
- Connector restart requires pairing again and cannot grant a different account.
- Exported host config contains no pairing code, device token or WeChat material.
- Remote host instructions never imply cloud-only web chats can reach localhost.
